# 狀態

詞彙見 `glossary.md`。寫入確認狀態只經過核心命令。頁面在打開另一張表之前，先保存目前表的用途。

## 未決：寫入用途要不要離開未看

兩邊都禁止把欄位自動標成已確認。分歧只有「寫下非空白用途」這一條，它會改變資料表確認狀態與進度。

- PRD FR-9 與架構 AD-3：未看 → 草稿（寫入用途，或起草成功寫入用途）。
- UX 的 UJ-2 與 purpose-editor：寫下用途後狀態仍是未看，要另一次明確的狀態動作才離開未看。

規格不代選。下游在這一條決定之前，不要各做一套彙總。

## 欄位確認狀態（兩邊一致）

允許：

- 草稿 → 已確認。用途必須非空白。
- 草稿 → 略過。
- 已確認 → 草稿。文字被改。
- 已確認 → 略過。
- 略過 → 草稿。寫入用途。
- 略過 → 未看。清除略過且用途為空。
- 未看 → 略過。

禁止：

- 未看 → 已確認。
- 任何自動程序把草稿改成已確認。
- 空白用途標成已確認。
- 確認檢視表。

略過的欄位沒有進入字典的用途句子。若原先有草稿文字，標成略過時文字留在解析專案，字典該列用途為空、確認狀態為略過。

未決只針對分析師手寫用途。起草成功寫入時，確認狀態成為草稿；這條沒有被 UX 反駁，起草本身也不在 MVP。已確認與略過不被起草覆蓋，除非分析師明示「重新起草已確認欄位」，該欄回到草稿並換上新文字與新依據。找不到可引用觀察時不寫用途，依據為「證據不足」，狀態維持未看。失敗不清除既有用途與確認狀態。

## 資料表確認狀態

由欄位彙總，頁面只顯示結果，不另設手動百分比。檢視表不適用、也不計入進度分母。

- 全部欄位為未看 → 未看。
- 全部欄位為已確認或略過 → 已確認。
- 其餘 → 進行中。

進度為「已確認張數 / 資料表總張數」，並另顯示進行中張數與未看張數。篩選不修改確認狀態。

## 關聯

- 宣告關聯來自目錄。重新讀取成功後，隨新快照整份更換。
- 推測關聯被接受前是待決定關聯，不進入圖、字典關聯表。
- 接受後成為已接受的推測關聯，之後的圖才畫出。
- 拒絕後留下已拒絕紀錄，不刪除該列。同一對不再自動提出。
- 手動建立必須指定兩端的表與欄。缺一端不能儲存。
- 接受、拒絕、手動建立與刪除只改解析專案。舊庫外鍵數量不變。
- 已接受的推測關聯若任一端在重新讀取後消失，不再入圖，標成端點已消失，並因此進入未確認清單。端點已消失不寫進結構變更。

## 誰下的結論

- 已確認的用途：只有分析師的明示確認。
- 草稿：分析師手寫，或起草。字典的依據欄必須讓讀者看出憑什麼寫下。
- 宣告關聯：舊系統資料庫目錄。
- 已接受的推測關聯：分析師的接受或手動建立。
- 待決定關聯：還沒有作者，因此不進圖。
- 分析包封面的時間與已確認比例表示某一刻的範圍，不是整座系統已分析完成。
