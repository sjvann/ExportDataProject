# 資料外洩審查 — Architecture Spine

審查對象：`ARCHITECTURE-SPINE.md`（未修改）
範圍：只看秘密與範例資料。守規則的實作是否仍會把連線字串、密碼、工作台原始範例、分析包、起草外送、日誌、錯誤訊息，或專案檔旁的 DPAPI 附檔帶出去。
判準：一條路徑必須同時守住 AD-6 的字面與相關 AD，才算本次要收的洞。明示例外（未遮罩開關、工作台原文）另記，不拿來充數。

## 已關上的出口

下列出口在字面上已經關住，本次不列為發現。

- 解析專案 JSON 不得含連線字串、連線密碼、資料列儲存格。寫入方式是暫存檔再改名（AD-2、AD-6）。
- 分析包組裝的輸入型別沒有連線字串。預設組裝只接收遮罩函式的結果（AD-6、AD-7）。
- 「包含未遮罩範例」預設關閉，打開時封面必須印「本包含未遮罩範例資料」，原文只活在該次組裝、不寫回文件（AD-6、AD-10）。這是明示例外。
- 工作台原始範例只允許出現在該次目錄讀取的回應（AD-6）。行程只聽 localhost（AD-8）。這是產品要的推想材料，不是靜默外送。
- 起草外送預設關閉；關閉時範例不得送出本機（AD-6，對應 FR-18）。
- 日誌可有表名、欄名與錯誤分類，不得寫連線字串與儲存格（AD-6）。
- 核心不引用 DPAPI。秘密庫是連接埠，實作在 `ExportDataWeb`（AD-1）。
- 命令列 CSV 不讀寫解析專案（AD-1、AD-7）。整庫原文匯出是既有命令列，不是分析包這條路。

## 守規則仍外洩的兩條路徑

### 路徑一 — 欄位預設值把識別值或密碼寫進專案檔與字典

嚴重性：高

守住的規則：

- AD-6 禁止的是連線字串、與連線字串並列的密碼、以及資料列的儲存格。欄位預設值三者都不是。
- AD-6 要求分析包輸入型別沒有連線字串，預設組裝只接收遮罩結果。遮罩結果指範例，不指目錄快照裡的預設值。
- AD-5 要求快照含預設值。既有目錄讀取已把 SQL Server `COLUMN_DEFAULT`、Oracle `DATA_DEFAULT`、MySQL `COLUMN_DEFAULT`、SQLite `dflt_value` 放進 `DefaultValue`。守規則的轉接器會繼續把這些字面常數放進快照。
- AD-2 把該快照寫進解析專案 JSON。
- AD-7 規定字典欄位以 FR-20 為準，其中有獨立的「預設值」欄，組裝器不增刪欄。遮罩函式不會走到這一欄。未遮罩開關是關的也一樣。

帶出去的方式：舊庫的預設字面常數（身分證、病歷號、預設密碼、預設帳號）進入解析專案檔，也進入交出的 `dictionary.csv`。封面不會出現「本包含未遮罩範例資料」，因為這不是範例欄。分析師依骨架末段自行複製專案檔時，同一批字面常數再離開一次。

這不是實作者違規。同時遵守 AD-5、AD-2、AD-6、AD-7 就會把這些值帶出去。

收緊：預設值裡的字面常數要與儲存格走同一個遮罩函式，才可以進專案檔與字典。序列、函數、不含字面常數的表達式可以留原文。空預設維持空。

### 路徑二 — 遮罩結果的首尾與形狀仍把識別值放進預設分析包和起草外送

嚴重性：高

守住的規則：

- AD-6 綁定 FR-23。預設組裝只接收遮罩結果，因此字典的範例欄不是原始儲存格。
- FR-23 的遮罩契約就是：先取至多三個相異原值，保留首尾各一字元（長度小於 4 則全遮），並附上形狀（最大長度、是否全為數字、是否含 `-` `/` `.`）。空值維持空。
- AD-5 規定有主鍵時範例依主鍵升冪。遮罩函式吃到的三個相異值，常常是最小的幾筆識別值。
- AD-7 把「遮罩範例」列進字典，組裝器不增刪欄。
- 起草外送打開時，AD-6 只要求先遮罩再送。送出去的範例同樣是這份首尾結果。

帶出去的方式：預設關閉未遮罩開關、也已經呼叫核心那一個遮罩函式之後，`dictionary.csv` 與外送內容仍帶識別值的首尾字元、長度與「是否全為數字」。身分證、電話、遞增主鍵都留得回形狀。長度小於 4 的短密碼會被全遮，長度較長的密碼仍留首尾。PRD 已聲明這不是去識別化；骨架的 AD-6 標題卻寫「儲存格不進入可匯出的模型」，規則正文沒有把這份殘留寫成可匯出模型的一部分。下游可以同時遵守 AD-6 與 FR-23，並把預設分析包說成沒有識別值。

收緊：在 AD-6 寫明預設分析包與外送允許的只有這份殘留，並禁止把殘留稱作不含識別值。若要連首尾一起擋住，必須改 FR-23 的遮罩契約，不能只改組裝器。

## 其他發現

### 用途與依據不經遮罩就進入分析包與外送

嚴重性：高

工作台回應裡的原始範例是 AD-6 允許的。分析師依這些值寫用途，或起草把觀察寫進依據。AD-3 要求用途全數保存、匯出不截斷。AD-7／FR-20 的字典含用途與依據。AD-6 的遮罩函式不處理這兩段文字。FR-17 的外送輸入還含「已確認的同表用途」與欄位結構；AD-6 只要求外送前遮罩範例。

守住這些句子時，寫進用途或依據的識別值、以及欄位結構裡的預設值，會以原文進入 `dictionary.csv`。外送開關打開時，範例已遮罩，這兩類文字仍原文離開本機。

收緊：進分析包與外送之前，用途與依據不得夾帶未遮罩的範例原文；欄位結構裡的預設字面常數與路徑一同一條規則。

### 建立失敗的回應可以回填整段連線字串

嚴重性：高

AD-6 的句子是「建立專案時，頁面把連線字串交給秘密庫後即不再放進回應或文件」。交給秘密庫之前的失敗（連線測試失敗、驗證失敗）不在這句裡。慣例只要求錯誤訊息可附「已去除連線字串的驅動程式原文」，沒有要求失敗頁的表單模型不得回填。既有首頁以 `asp-for` 綁連線字串，失敗時回到同一頁就會把含 `Password=` 的原文畫回文字區。

守住「手交之後才禁止」與「驅動程式原文去掉連線字串」時，密碼仍在該次 HTML 回應裡。四種驅動的常見 `Message`（例如 ORA-01017、登入失敗）本身通常不回顯密碼值；缺口在表單回填，不在驅動程式原文。

收緊：失敗回應也不得回填連線字串或密碼。錯誤原文除了去掉整段連線字串，還要去掉 `Password`、`Pwd`、`Proxy Password` 的值，避免驅動程式改寫鍵序後對不上原文。

### DPAPI 附檔可以跟著分析包目錄離開

嚴重性：高

AD-6 把秘密放在專案檔旁邊的 DPAPI 附檔，並只禁止連線字串進入「解析專案文件」與「分析包輸入型別」。AD-7 規定產出目錄要有 `cover.md`、`dictionary.csv`、`relations.csv`、`open-items.csv`、`er.svg`，沒有說這個目錄必須是空的新目錄、不得與專案目錄相同、也沒有說打包時只能含這五個檔。AD-1 讓 `ExportDataWeb` 同時實作秘密庫與寫出側；組裝器看不到連線字串，輸入型別這句仍然成立。

守住上述句子時，五個檔寫進專案目錄，附檔本來就在旁邊。分析師複製該目錄或把目錄當成分析包帶走時，密文一起走。骨架沒有寫 `DataProtectionScope`。同一 Windows 使用者可解密；範圍若做成機器層級，同機其他使用者也可解密。

收緊：分析包目錄必須是新目錄，且只含 AD-7 的五個檔。附檔不得複製進去。秘密庫寫明只保護目前使用者、不隨目錄交付。
