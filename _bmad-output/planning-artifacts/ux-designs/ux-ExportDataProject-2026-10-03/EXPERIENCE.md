# ExportDataProject — Experience Spine

行為契約。視覺在 `DESIGN.md`。四個表面都沒有 mock。實作以這兩份契約為準；契約與畫面稿衝突時，以契約為準。

## Foundation

單一表面：本機 Web。[ASSUMPTION] 既有實作是 ASP.NET Razor Pages 加上 Bootstrap 5.3.3。本文件只寫與 Bootstrap 預設不同的行為；視覺差異寫在 `DESIGN.md`。

操作者是林安，系統整合案的系統分析師。一個解析專案、同一時間一個人。她要做的事是連上舊系統資料庫，看懂資料表，寫下用途，留下已確認，再把看過的範圍交成分析包。整庫匯出 CSV 只是取樣手段。

使用者已決定：這個產品賣給客戶，讓客戶自己去整合，就和賣方自己去接整合專案一樣。PRD 的「內部工具」與此衝突，體驗以這個決定為準。林安是買下產品後自己接案的分析師。

客戶買到的就是 UJ-1、UJ-2、UJ-3，而且可以獨立走完。連線之前、分析包之後，都沒有另一個必做步驟。因此這一版沒有報價、合約、資料搬移、帳號、計費、獨立行銷網站或代管服務。[ASSUMPTION] 產品名稱未定，空的首頁不用 ExportDataWeb 當標題。

介面固定標題與分析包固定標題為繁體中文。表名、欄位名不翻譯。文件語言 `zh-Hant`。

MVP 走到 UJ-1、UJ-2、UJ-3。模組、推測關聯、起草、UML 類別圖在 MVP 之後；資訊架構保留位置，流程不把它們寫成第一輪的高潮。

## Orientation

還沒有解析專案時，`product-promise` 先回答這個產品做什麼。已有專案之後，每一個表面用畫面上的字回答三句，不靠作者在旁邊說明：

1. 現在是哪一個解析專案。
2. 這一頁是在連線、看表，還是交出。
3. 下一個動作是什麼。下一個動作通常是「下一張未看」。

連線還沒成功時，不顯示一張空的資料表清單充當進度。工作台某一塊失敗時，另外兩塊仍可讀，並寫出失敗原因。

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 解析專案首頁 | 打開本機 Web；由工作台或匯出返回 | 建立或開啟解析專案、測試唯讀連線、看資料表清單與進度、進入下一張未看、另進匯出 |
| 資料表工作台 | 清單列，或「下一張未看」 | 同一頁看結構、範例資料、鄰居圖；寫用途；把欄位推到已確認 |
| 匯出 | 首頁上的次要入口 | 選範圍、決定範例是否遮罩、產生分析包 |
| 模組 | 清單的前綴或勾選 | 非 MVP。整群表的實體關係圖與 UML 類別圖 |

主行動是「繼續下一張未看」。匯出不是首頁主行動。CLI 匯出不承載 UJ-1、UJ-2、UJ-3。

名詞以 PRD 詞彙為準，介面上要出現的有：解析專案、舊系統資料庫、資料表、欄位、宣告關聯、鄰居圖、用途、依據、確認狀態（未看、草稿、已確認、略過）、資料表確認狀態（未看、進行中、已確認）、分析包、資料字典、未確認清單、遮罩範例、實體關係圖。基數只用 `0..1`、`1`、`0..*`、`1..*`、未明。

## Voice and Tone

品牌語氣在 `DESIGN.md` 的 Brand & Style。這裡只定微文案。對林安說話：短、具體、告訴她現在能做什麼。不歡呼，不責備，不把狀態說成系統術語編號。

| Do | Don't |
|---|---|
| 「用來接一座舊系統的整合專案：連上資料庫，看懂每一張表，交出分析包。連線只讀取，不修改舊系統。」[ASSUMPTION] 這是空首頁的工作描述，產品名稱定了再換標題。 | 用 ExportDataWeb 或倉庫名稱當產品標題 |
| 「下一張未看」 | 「開始匯出」當已有專案時的主按鈕 |
| 「認證失敗。專案已留下，尚未讀到資料表。」 | 「0 張表」 |
| 「目錄中沒有宣告關聯」 | 空白圖，不說明 |
| 「沒有列」 | 用假資料填空表 |
| 「此範圍沒有未確認項目」 | 未確認清單省略不給 |
| 「本包含未遮罩範例資料」 | 只靠顏色表示有敏感範例 |
| 「證據不足」 | 自動寫成已確認 |
| 「連不上主機」「沒有讀取目錄的權限」「類型與連線內容不符」 | 「發生錯誤」 |

## Component Patterns

視覺規格在 `DESIGN.md` Components。同一元件用同一名稱。

| Component | Use | Behavioral rules |
|---|---|---|
| product-promise | 解析專案首頁，尚無專案 | 放在 `connect-form` 之上。說明這是用來接一座舊系統的整合專案：連上資料庫、看懂每一張表、交出分析包，而且連線只讀取、不修改舊系統。密碼欄出現之前就能讀到。一旦專案建立，這塊離開。 |
| next-step-bar | 解析專案首頁、資料表工作台 | 顯示專案名、目前表面、已確認表數／總表數，以及進行中與未看的數量。填色按鈕只有「下一張未看」。沒有未看的表時，按鈕改為不可按，文字改「沒有未看的表」，不改去導向匯出。 |
| connect-form | 解析專案首頁 | 建立解析專案：名稱、資料庫類型、連線、測試連線。只建立唯讀連線。測試成功才進入盤點。密碼欄前已由 `product-promise` 說明不會修改舊系統。密碼與連線字串不進入分析包、日誌與錯誤訊息。 |
| connection-failure | 解析專案首頁，連線或盤點失敗 | 四種原因分開寫：連不上主機、認證失敗、沒有讀取目錄的權限、類型與連線內容不符。保留尚未盤點的專案。不建立看起來像「這座庫沒有表」的清單。 |
| table-list | 解析專案首頁 | 連線成功後列出資料表。可搜尋、以前綴篩選、可排序。每一列帶確認狀態。點列進入該表的工作台。約略筆數讀取失敗時該列顯示「未知」，其他表照列。目標規模至少 500 張表仍可搜尋篩選。[ASSUMPTION] 這個數字來自 PRD 假設，不是另定的互動上限。 |
| status-badge | 清單、工作台、分析包預覽 | 欄位只有四態：未看、草稿、已確認、略過。只有分析師能推進；沒有自動確認。資料表由欄位彙總為未看、進行中、已確認。詞與顏色同時出現。 |
| workbench | 資料表工作台 | 一頁同時呈現結構、範例資料、鄰居圖。不拆成三次送出。三塊各自載入；任一塊失敗不拆掉另外兩塊。 |
| purpose-editor | 工作台的結構區 | 可寫表用途與欄用途。寫下用途不會自動變成已確認。分析師另按狀態動作才離開未看。略過須是她的動作，用來跳過她判斷不必確認的欄，例如稽核欄。 |
| sample-region | 工作台 | 預設 20 列，上限 100，用來判斷形態，不是整表瀏覽。空表顯示「沒有列」，結構仍在。工作台顯示原始範例。 |
| neighbor-graph | 工作台 | 只畫一層父表與子表。線來自目錄中的宣告關聯。基數看鍵的性質；推不出就標未明。點鄰表開啟該表工作台。沒有宣告關聯時只留目前表，並寫「目錄中沒有宣告關聯」。欄位顯示預設「僅鍵」。 |
| partial-failure | 工作台分區 | 結構、範例、鄰居圖任一失敗，該區顯示原因，另兩區可繼續用。起草失敗（MVP 之後）也走同一規則：工作台仍可手工分析。原因包含未載入範例資料、連線中斷、起草元件無回應。 |
| export-panel | 匯出 | 先選範圍：目前資料表及其鄰居，或手動勾選。預設產出遮罩範例。可明確打開「包含未遮罩範例」，打開後封面須能讀到「本包含未遮罩範例資料」。產生分析包。已確認比例為 0 仍允許產生；包內把已確認與未確認清單分開。密碼不進包。未確認清單永遠在；沒有項目時檔案仍在，內容為「此範圍沒有未確認項目」。 |

MVP 的鄰居圖只畫宣告關聯。待決定關聯、接受後才上圖、模組圖、UML，都在 MVP 之後，不出現在第一輪工作台的預設路徑裡。

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 尚未有專案 | 解析專案首頁 | `product-promise` 在上，`connect-form` 在下。主行動是建立唯讀連線。 |
| 連線中 | 解析專案首頁 | 測試連線按鈕進入等待。不先列出 0 張表。 |
| 連線失敗 | 解析專案首頁 | `connection-failure` 的四種原因之一。專案留著，清單不假裝盤點完成。 |
| 盤點完成 | 解析專案首頁 | `table-list` 加上進度。主行動「下一張未看」。 |
| 冷載入工作台 | 資料表工作台 | 三個分區先佔位，載入完成的分區先可讀，不互相等待。 |
| 空表 | 資料表工作台 | 結構仍在。範例區寫「沒有列」。 |
| 無宣告關聯 | 資料表工作台 | 鄰居圖只留目前表，文案「目錄中沒有宣告關聯」。 |
| 分區失敗 | 資料表工作台 | `partial-failure`。另兩區保持可操作。 |
| 欄位未看 | 工作台、清單 | 標章「未看」。沒有用途也可以。 |
| 欄位草稿 | 工作台 | 標章「草稿」。草稿不是已確認，匯出時不得讀成已確認。 |
| 欄位已確認 | 工作台 | 標章「已確認」。只有分析師的動作能進入此態。 |
| 欄位略過 | 工作台 | 標章「略過」。 |
| 沒有未看的表 | 首頁、工作台 | 「下一張未看」不可按，並說明沒有未看的表。 |
| 匯出範圍是空的 | 匯出 | 不能產生。說明先選擇資料表。 |
| 未遮罩已打開 | 匯出 | 警示「本包含未遮罩範例資料」，直到她關閉開關。 |
| 匯出完成但無人確認 | 匯出 | 允許完成。結果說明已確認與未確認清單是分開的。 |
| 匯出產生中 | 匯出 | 「產生分析包」進入等待。範圍與遮罩選擇留在畫面上。 |
| 重新讀取結構 | 工作台、清單 | 保留已寫的用途與確認狀態。消失或新增的表要標出來，不靜默刪除她的結論。 |
| 模組 | 模組 | 不在這一版的三步裡，沒有畫面狀態。 |

[ASSUMPTION] 沒有產品級離線模式。連線中斷時，已開著的結構若還在畫面上就留著，範例與重新讀取失敗走 `partial-failure`。分析包的圖與資料字典在產生當下不依賴外部網路。

## Interaction Primitives

滑鼠為主。林安的工作是對照欄位與範例，不是記捷徑。

- 測試連線、進入工作台、確認狀態、產生分析包，都可用點選完成。
- 清單可搜尋、篩選前綴、排序。
- 鄰居圖的節點可點，開啟那張表。
- 狀態動作（未看、草稿、已確認、略過）是明確按鈕或同等的明確控制，不是點一下儲存格就連帶確認。
- [ASSUMPTION] 鍵盤至少能走完連線表單、清單搜尋，以及工作台上的用途與狀態控制。焦點環使用 `{colors.focus}`。不把捷徑當成唯一路徑。

禁止：

- 首頁以「匯出全部」當主行動。
- 自動確認欄位。
- 把結構、範例、關聯拆成三個各自送出的頁面。
- 由圖編輯回寫資料庫結構。
- 只靠顏色表示確認狀態。
- 連線失敗時展示空庫。

## Accessibility Floor

視覺對比在 `DESIGN.md` Colors。[ASSUMPTION] PRD 沒有無障礙規格。本層假設：

- 林安能只用鍵盤完成 UJ-1 到 UJ-3 的主路徑：建立連線、從清單進入一張表、寫下一個欄位用途、標成已確認、產生預設遮罩的分析包。
- 確認狀態不只靠顏色。
- 焦點始終可見。
- 錯誤訊息寫在失敗的區塊裡，並可被讀取，不只靠顏色邊框。
- 圖上的「目錄中沒有宣告關聯」與基數「未明」有文字，不只有線條。
- 介面語言為繁體中文，識別名保持原文，讀屏時兩者都讀得出來。

## Inspiration & Anti-patterns

- 市場上要讓人留下的差異，用產品行為呈現：同一頁對照範例與用途、確認狀態寫進分析包、圖上只出現已納入的關聯。介面裡不點名其他產品。
- 從 PRD 留下的：分析包要讓沒有操作過程的人分得清已確認與未確認。這決定匯出結果的資訊結構。
- 拒絕把現有「匯出 CSV 當首頁」延續為主路徑。
- 拒絕把結構、範例、關聯分成三次送出。FR-5 要求同一工作台。
- 拒絕圖上編輯後回寫結構。v1 不做。
- 拒絕自動起草後直接已確認。證據不足時維持未看，依據寫「證據不足」。起草本身不是 MVP。
- 拒絕用整庫大圖或 CSV 筆數當作做好了的訊號。

## Key Flows

### UJ-1. 林安連上舊庫，先知道這座庫有多大、從哪裡看起。

1. 林安買了這個產品來接一座舊系統的整合專案。首頁先寫她要做的事，和賣方自己接案時相同：連上資料庫、看懂每一張表、交出分析包，連線只讀取。
2. 她建立解析專案，選擇資料庫類型，填入唯讀連線，按下測試連線。
3. 連線成功後，清單出現資料表、關聯規模、前綴與確認狀態。她用前綴縮小範圍。
4. **高潮：** 她按下「下一張未看」，或打開一張被很多表參照的表，進入工作台。她還沒有、也不需要做整庫匯出，就知道從哪裡看起。

失敗：認證失敗或其他三種連線失敗。畫面留下這個還沒盤點的專案，寫出原因。她看不到一張「0 張表」的清單。

### UJ-2. 林安在同一張畫面看懂一個欄位，並留下已確認。

1. 林安在 `REG_MST` 的工作台。同一頁有欄位結構、少量範例列、一層鄰居圖。
2. 她對照範例，在 `purpose-editor` 寫下一個欄位的用途。狀態仍是未看。
3. 她若判斷某個稽核欄不必確認，就把它標成略過。這是她的動作。
4. **高潮：** 她把看懂的那個欄位標成已確認。進度增加。她沒有離開這張畫面，也沒有打開外部畫圖工具。

失敗：範例區載入失敗。結構與鄰居圖仍在，範例區寫出原因。她仍可依結構手寫用途。若這張表沒有列，範例區寫「沒有列」，不補造資料。

### UJ-3. 林安把看過的範圍交成系統分析文件。

1. 林安從首頁的次要入口進入匯出。首頁的填色按鈕仍是「下一張未看」。
2. 她選擇「目前資料表及其鄰居」，或手動勾選一組表。
3. 遮罩維持預設開啟。她看到將交出的範圍，然後按下產生分析包。
4. **高潮：** 她得到分析包。資料字典、實體關係圖、未確認清單與封面在一起。已確認與尚未確認分開。檔案裡沒有密碼。沒看過這次操作的人，只讀這個包也分得清哪些已確認。

失敗：這個範圍一筆都還沒有已確認。系統仍交出分析包，未確認清單讓那些列不能被讀成已確認。若她改為包含未遮罩範例，完成前與封面上都有「本包含未遮罩範例資料」。
